# Decisions

Settled with the owner while extracting `agent-evals` from inquirex-llm's `extract-eval` suite (2026-10-14).

| #   | Question                                  | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| --- | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Where is the boundary?                    | One way. The suite registers an `Adapter` (runs one case against a `Model`, returns a `Reply`, never scores) and a `Scorer` (pure, returns a `Score`, never calls anything). `rg -i inquirex lib` is empty.                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| 2   | Namespace, gem, executable                | `Agent::Evals`, gem `agent-evals`, `require "agent/evals"`, executable `agent-evals`. Ruby >= 3.4, developed on 4.1.0-preview1.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| 3   | How does a suite reach the runner?        | `evals/eval_helper.rb` calling `Agent::Evals.configure`, found upward from the working directory, or `--helper PATH`, or `AGENT_EVALS_HELPER`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| 4   | Cases on disk                             | `datasets/<dataset>/cases/<variant>/[NNN/]input.txt` with `expected.json` beside; any other layout through the glob given to `c.cases`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| 5   | What is an error, what is a wrong answer? | A `Reply` with `error` set is the model's failure and scores 0 on every metric. An exception from the adapter is the transport's, counted as a run error with no score.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| 6   | Metrics                                   | The scorer declares `Metric`s; the CLI derives its columns, glossary, ranking (the `primary`) and best value from them. Means skip nil, so a metric a case does not apply to never adds a free 0 or 1.                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| 7   | Optional gems                             | `ruby_llm` and `braintrust` are not runtime dependencies. They are required when a command needs them, with an error naming the gem.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| 8   | Local runs                                | Superseded by 16: the gem's own thread pool runs every experiment; nothing ever goes through `Braintrust::Eval.run`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| 9   | Providers                                 | A registry asked last-registered first; OpenRouter claims every id and is always last. A suite's own transport is registered with `c.provider`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| 10  | TypeSafe                                  | `Providers::TypeSafe` holds the catalog, the key and the pricing of TypeSafe's API, for `verify` and the cost column. Its `complete` raises: there is no typesafe consumer yet.                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| 11  | Command line                              | dry-cli: `cases`, `verify`, `run`, `compare`, `version`, `completion`. `-n` on every command that calls models; `-o` for the report; `-l`/`-L` reserved.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| 12  | Tests                                     | Real temp directories, no filesystem mocks, no network: `RubyLLM`, `Braintrust::Eval` and `Net::HTTP` are stubbed. A toy suite under `spec/fixtures/toy_suite/` proves the executable end to end. Coverage floor 95%.                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| 13  | The lineup file                           | `.agent-eval.config.yml` at the suite root: `project`, `request_types`, `defaults` (effort, temperature, max_tokens, parallelism), `vendors` (the OpenRouter list, every entry a prompt) and `direct` (a vendor's own API, keyed by provider name, same entry format). Lists of effort and temperature expand into contenders; `defaults.parallelism` is the default for `-p`. A direct contender carries its provider, so `typesafe/jev-latest` under `direct:` and `typesafe/jev-router` under `vendors:` cannot collide.                                                                                                                             |
| 14  | Who declares the request type?            | The suite's config, not code. `request_types` is required and lists what the adapter sends; the provider owns what a type means (`prompt`: a chat completion; `typesafe`: noul, choice, score), shown in `--help` and never spelled in a suite's config. A contender whose provider's type is not declared is refused by name in the warnings and excluded, never scored 0. inquirex-llm is `[prompt]` by definition: it extracts a whole schema from free text. There is no `typesafe-api` vendor: `typesafe: jev-router` stays under `vendors:` as a chat model, and TypeSafe's own API is `direct: typesafe:`.                                       |
| 15  | Can a suite be config-only?               | Yes. `require:` (a path or list), `adapter:` and `scorer:` (constant names, built with no arguments) in `.agent-eval.config.yml` supply what `eval_helper.rb` would. The helper, when present, loads first and wins; the config fills what it left unset; neither is an error naming the file and the keys, and a failed require or unknown constant names the key and the value. The first consumer, inquirex-llm, is config-only: `evals/` holds the file and `datasets/`, its Ruby lives under `lib/inquirex/llm/evals/`.                                                                                                                            |
| 16  | Where do results go?                      | Trackers. agent-evals always owns the run loop; a `Tracker` only receives `start`, `record` and `finish`. The local JSON log under `log/agent-evals/` always runs; exactly one remote tracker runs beside it, or none, chosen by `--tracker`, then `tracker:` in the config, then the one env key that is set (two set and none chosen is an error). Shipped: `braintrust` (eval rows through the gem's exporter) and `logfire`, which is no Ruby gem but an OTLP backend for the OpenTelemetry Ruby SDK (traces only, one span per experiment, one per case, replies opt-in). A Weave or other OTLP tracker is a subclass registered with `c.tracker`. |

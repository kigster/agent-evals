# Decisions on agent-evals and the Inquirex extraction suite

Settled with the maintainer on 2026-10-14.

| #   | Question                   | Decision                                                                                                                                                                                                                                                                            |
| --- | -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Where the runner lives     | A separate gem, `agent-evals` (github.com/kigster/agent-evals, namespace `Agent::Evals`). One-way dependency: inquirex-llm depends on it; it never references Inquirex.                                                                                                             |
| 2   | What stays in inquirex-llm | The ten DSLs, per-dataset schemas, inputs, expected outputs, `InquirexAdapter`, `StructuredOutputScorer`, `evals/eval_helper.rb`, `config.yml` (the model lineup).                                                                                                                  |
| 3   | Layout                     | `evals/datasets/<NN-slug>/{dsl.rb,schema.rb,cases/<variant>/[NNN/]{input.txt,expected.json}}`.                                                                                                                                                                                      |
| 4   | Variants                   | `complete` (was `clear`) and `vague`. `conccise` is a byte-identical copy of `vague` and is dropped; the maintainer will write real `concise` texts.                                                                                                                                |
| 5   | What the scorer sees       | Both views from ONE LLM call. The gem's adapter returns an `Extraction` object carrying `raw` (parsed JSON as the model sent it), `output` (normalized, what the form prefills) and `usage`. It behaves like the hash it replaces, so application callers do not change.            |
| 6   | Outcomes come from `raw`   | The eval measures the model, not the code that repairs its answers. A value outside the schema's list, a wrong type or an unknown field is `invalid`, even when `normalize_output` would have repaired or nulled it. The normalized value is kept in the diagnostics for reference. |
| 7   | Per-field outcomes         | `correct` (matches the truth, including `null` where the text does not answer), `missed` (text answers, model returned `null`/absent), `hallucinated` (a valid schema value the text never supports), `incorrect` (text answers, model picked a different valid value), `invalid`.  |
| 8   | Weights                    | correct 1.0, missed 0.2, hallucinated 0.15, incorrect 0.1, invalid 0. Score = mean over schema fields, already in 0–1: no rescaling, no clamping. An empty reply scores 0.2; a non-JSON reply is all `invalid`, 0.                                                                  |
| 9   | Multi-enum                 | Partial credit per element: present in both → correct, only in truth → missed, only in reply → hallucinated, off-list → invalid. The field's weight is the mean of its elements.                                                                                                    |
| 10  | Missing keys vs `null`     | Every schema field must be present in the reply; unanswered ones are `null`. An absent key scores as `missed` plus a "key absent" diagnostic. `""`/`[]` against a `null` truth count correct with a form-drift diagnostic; `0`/`false` against a `null` truth are `hallucinated`.   |
| 11  | Metrics                    | `score` (the mean above), `exact` (every field correct), `hallucinated_rate`, `invalid_rate`. The old `restraint` scorer is absorbed into `hallucinated_rate`. Metric names come from the scorer, not the CLI.                                                                      |
| 12  | Dependencies               | Braintrust and RubyLLM are optional in agent-evals, required lazily by the commands that need them.                                                                                                                                                                                 |
| 13  | Old results                | The 2026-10-14 README tables stay, labelled with the old scorer; new runs start new tables.                                                                                                                                                                                         |

Still open: whether the `TypeSafe` provider stub stays in agent-evals or moves next to the Jev code in inquirex-llm (recommendation: move).
